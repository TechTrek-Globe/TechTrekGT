# Finance OS - Features & API Specification

## 1. Feature Suite

Finance OS is the personal budget tracking and financial projection application in TechTrekGT:

- **Daily Matrix & Cash Flow Forecasting:** 365-day running balances, paycheck allocations, split earner credits, and overdraft prevention.
- **Ledger Import & Reconciliation:** Dedicated Web Worker (`spreadsheet.worker.js`) offloads heavy SheetJS (`xlsx`) file parsing off the main browser thread to prevent UI freezing.
- **Budget Metadata Management:** Multi-account checking/savings management, bill scheduling with variable/fixed frequencies, funding goals, and amortized loan tracking.
- **Cloud Vault & Multi-Version Backup:** Optimistic concurrency sync against Cloudflare D1 with up to 10 historical rollback snapshots.
- **SSO Authentication & Session Management:** WebCrypto HS256 JWT sessions, PBKDF2-SHA256 password hashing (600,000 iterations), double-submit CSRF protection, and HttpOnly `SameSite=Strict` cookies.

## 3. Data Integrity & SQL Parameterization (FIN-AUDIT-001)

- **Strict SQLite Parameterization:** All queries use `db.prepare(sql).bind(...)` with `?` positional parameters. No template literal variable interpolations exist in any API route or utility.
- **Compensating Rollbacks:** In multi-step database mutations, catch blocks surgically execute compensating D1 statements to delete incomplete, orphaned, or unlinked records on downstream failure.

## 4. Authentication, Authorization & Session Lifecycle (FIN-AUDIT-002)

- **HttpOnly Cookie Standard:** Authentication strictly utilizes `HttpOnly; Secure; SameSite=Strict` cookies (`auth_token` and `csrf_token`) scoped to `/finance` and `/api`. No tokens are accessible to client JavaScript or stored in `localStorage`.
- **Immediate Credential Purging:** Failed token validations (signature mismatch, expired TTL, revoked session, or suspended account) actively purge invalid credentials via `clearedCookies()` (`Max-Age=0`) alongside explicit HTTP 401/403 responses.
- **Atomic Session Invalidation:** Password resets (`reset-password.js`), profile password updates (`update-profile.js`), email change confirmations (`confirm-email-change.js`), account suspensions (`admin/user-status.js`), and user logouts (`logout.js`) increment `token_version` in D1 and invalidate the session cache (`invalidateCachedUser`), invalidating all existing JWTs for that account immediately.
- **Multi-Cookie Resolution:** Handles browser cookie multi-path collisions by evaluating all candidate `auth_token` cookies in sequence (`getAllTokensFromRequest`), preventing subpath cookie shadowing. Rejects mixed-credential requests (Cookie + Bearer) with HTTP 400.
- **Standardized Route Guards:** Shared `requireAuth` and `withAuth` guards enforce session validity and reject invalid or revoked states with standardized error codes without exposing backend internals.
- **Fail-Closed Security Headers & Origin Strictness (FIX-12):** Removed `http://techtrekgt.com` from `PRODUCTION_ORIGINS` to reject unencrypted HTTP origins. Removed `Boolean(url.port)` from the `isLocalhost` check. Enforced fail-closed security header posture: CSP and HSTS are applied by default across all requests (including unset `ENVIRONMENT` or port-bearing URLs) unless `ENVIRONMENT` is explicitly 'development' and the request hostname is `localhost` or `127.0.0.1`.

## 5. Financial Math Engine & Calculation Safety (FIN-AUDIT-003)

- **Deterministic Rounding Utility (`round2`):** Eliminates IEEE 754 floating-point inaccuracies (e.g., `0.1 + 0.2 = 0.30000000000000004`) across all client and backend operations. Incorporates `Number.EPSILON` boundary preservation (`Math.round((val + (val >= 0 ? Number.EPSILON : -Number.EPSILON)) * 100) / 100`) to guarantee deterministic banker-grade rounding on half-cent thresholds.
- **Robust NaN & Non-Finite Defense:** Sanitizes all monetary inputs (`parseMoney`, `validateNonNegativeMoney`, `cleanNum`) against `NaN`, `Infinity`, `-Infinity`, `null`, `undefined`, and empty strings. Never permits `NaN` or `Infinity` to propagate into the daily matrix, running balances, or state tree.
- **Currency & Accounting Parser Hardening:** Strips leading/trailing whitespace, dollar signs (`$`), and thousand separators (`,`) before numeric conversion. Automatically parses accounting negative notation (e.g., `($1,234.56)` or `(45.00)`) into negative numbers.
- **Cent-Exact Credit Allocation Invariant:** In `allocateEarnerCredit`, regular operating credits and extra savings deposits adhere strictly to the invariant `earnerReg + earnerExtra <= earnerDeposit`, clamping extra savings to prevent over-allocation and ensuring exact penny preservation.
- **Stored Past Credit Resolution & Multi-Account Projection:** In `allocateEarnerCredit`, stored non-zero credits take precedence and display their stored values while stored zeros display "$ -". Supports account-scoped resolution and aggregated "All Accounts" views without dropping manual overrides or off-payday historical records.
- **Safe Arithmetic Helpers:** Shared utilities (`safeAdd`, `safeSub`, `safeMul`, `safeDiv`) guarantee that all arithmetic operations produce normalized 2-decimal numbers with built-in zero-division protection (`safeDiv(val, 0) === 0`).
- **Ending Balance Invariance & Bank Variance Indicator (FIX-08):** In `LedgerView` (`matrixData`), `LedgerDataContext` (`getCalculatedBalanceAsOf`), and `spreadsheet` (`getLedgerRunningBalanceAsOfDate`), ending balances strictly follow the ledger matrix formulas: Reg Beg + Extra Beg = Total Beg; Reg Beg - Bills and Deductions (except Other $) = Reg End; Extra Beg (+/-) Other = Extra End; Reg End + Extra End = Total End; Extra = Extra Payment Goal for account +/- Other $. Stored ending balances (`reg_ending`, `extra_ending`) and `importedLedgerRows` are never used to overwrite calculated ending values; they are preserved unchanged solely for statement comparison. Bank variance strictly relates to Total End (`round2(totalEnd - bankBalance)`), never Reg End alone, because bank statement balances represent overall account liquidity. When `|totalEnd - bank| > 0.01`, the row is marked with a visible 'Differs from bank by $X' indicator featuring both text and an AlertTriangle icon placed directly in the sticky right Total End column, and the variance is exposed in row data (`bankBalance`, `variance`, `hasBankDiff`, `bankDiffText`). Chronological import order detection in `importer.js` and `spreadsheet.js` preserves the day's true ending balance across newest-first and oldest-first files.
- **Consistent Credit Rule & Pay Period Deduplication (FIX-09):** Across all three engines (`LedgerView`, `getCalculatedBalanceAsOf`, and `getLedgerRunningBalanceAsOfDate`), a unified lock boundary applies: `lock end = min(last imported date, today)`. On locked dates (`isoDate <= lock end`), only stored or imported credits appear; projected credits are never added. Imported bank credits land on the bank date. When an imported credit for an earner exists within a pay period, the scheduled payday's projected credit for that earner is suppressed, preventing duplicate credits within the same period. All three engines return identical `reg`, `extra`, and `total` balances across all dates.
- **Archived Bills Calculation Invariant (FIN-LEDGER-002):** Bills marked as `isArchived` correctly preserve historical ledger math without projecting into the future. Archived bills apply imported actuals and manual matrix overrides exactly as active bills do, but bypass standard scheduled projections (`expectedBillAmt`). This guarantees past `Reg End` totals remain accurate after an active bill is archived, while halting its future cash-flow impact.
- **Bank Import Ending Balances & Comparison Data (FIX-10):** In `spreadsheet.js` (`processSpreadsheetImport`), bank statement imports no longer write `reg_ending` cells to `dailyMatrix`. Bank running balances are stored strictly in `account.importedLedgerRows` on the target account for statement comparison and variance tracking. Existing `reg_ending` keys in `dailyMatrix` are preserved untouched and continue to be ignored during row calculations (per FIX-08).
- **Spreadsheet Parser Upgrade & Input Safeguards (FIX-11):** Upgraded `xlsx` to the official pinned SheetJS release (`https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`), eliminating npm audit high-severity advisories (GHSA-4r6h-8v6p-xvw6, GHSA-5pgg-2g8v-p4x9). Parsing executes in a dedicated Web Worker (`spreadsheet.worker.js`), with strict pre-parsing size constraints enforcing a maximum file size of 15MB (`MAX_SPREADSHEET_FILE_SIZE`) and a maximum worksheet limit of 50,000 rows (`MAX_SPREADSHEET_ROW_COUNT`).
- **Removal of Household Data & Heuristic Keyword Matching (FIX-13):** Completely scrubbed household-specific account names, last-four digits, earner IDs, fixed default balances, and heuristic keyword matching (`mortgage`, `hoa`, `bills`) across `spreadsheetParser.js`, `importer.js`, `paydayUtils.js`, `budgetMigrations.js`, `LedgerDataContext.jsx`, `AccountsPeoplePanel.jsx`, and demo presets. Replaced the hardcoded `$1,600 verified` check with a generic goals-versus-bills coverage indicator comparing total monthly goals to total monthly bill obligations. Generic CSV imports create zero hardcoded accounts or people.
- **Removal of Magic-Number Bill Rewrites (FIX-14):** Removed silent bill amount overrides (`442.32` and `2601.45 / 2757.68`) from `BudgetMetadataContext.jsx`. Stored bill amounts are preserved exactly across reloads. Added `proposeLegacyBillCorrections` to `budgetMigrations.js` for explicit owner review and approval without mutating real data.
- **Independent Earner Credit Offsets (FIX-15):** Corrected the mathematical regression in `allocateEarnerCredit` where a negative extra savings override artificially inflated the regular credit portion. Negative extra offsets are now preserved and subtracted from the extra savings balance independently, without mathematically inflating the regular balance, ensuring "Reg Beg" and "Extra Beg" compute their true independent starting balances without double-counting.
- **Unbudgeted Transactions Routing & Ledger Deficit Transfer (FIX-16):** Unbudgeted "Other $" amounts are added to the regular operating ending balance (`regEnding = round2(runningRegBeg + totalRegCredits - totalDayBills + otherAmt)`), matching the cash-flow convention that miscellaneous checking deductions drain primary operating cash rather than reserved extra savings. Added bidirectional deficit transfer balancing between `regEnding` and `extraEnding` so that accounts never maintain a negative Extra Savings ending or beginning balance while Regular operating funds remain positive. Introduced Schema Version 3 (`healCorruptedLedgerRows` in `budgetMigrations.js`) which heals legacy negative `extraStartingBalance`, `extraEnding`, and `extraBeg` entries across user accounts and cloud storage backups.
- **Merge Matching & Full-Clear Override (FIX-17):** Merge imports now pair incoming bank rows to existing ledger transactions using a shared logical matcher (`isSameLogicalTransaction` in `importer.js`): exact date+amount matches deduplicate silently, description-matched rows within a 31-day window auto-merge and update the payment date to the bank's posted date (no duplicates), and amount disagreements within that window are surfaced as review-required conflicts in the RECONCILIATION stage instead of being silently appended. Override imports fully replace the transaction grid, daily matrix, and line items with only the imported Credits/Debits rows (no date-scoped or account-scoped preservation), so post-import running balances reconcile exactly against the imported bank statement.
- **Synchronized Backend Payload Validation:** Cloudflare Workers endpoints share the deterministic currency parser and validator (`validateNonNegativeMoney`, `round2`), guaranteeing identical math across client state and D1 database persistence.

## 6. Frontend State Management & UI Synchronization (FIN-AUDIT-004)

- **Audit Objective & Scope:** Comprehensive audit of React context providers (`AuthContext`, `BudgetMetadataContext`, `LedgerDataContext`), custom hooks, and component lifecycles to eliminate stale state caching, false-positive success indicators, and unhandled promise rejections.
- **Multi-Account Context Isolation on Sign-Out:** Implemented the `techtrek:user-logout` global event channel. When a user logs out, all React contexts immediately purge active budget metadata, accounts, earners, bills, daily matrix projections, and historical line items from memory before the new session begins.
- **Strict User Scoping across Local Storage & Sync Queues:** IndexedDB reads and writes, pending mutation queues (`getPendingSync`, `clearPendingSync`, `flushPendingCloudSync`), and cloud version markers are partitioned strictly by `userId`.
- **Guaranteed Loading State Resets:** Wrapped all asynchronous UI mutations across the application (email verification, code resend, disk cache flush, matrix cleanup, standard goal restore, admin user status toggle) in `try ... finally` blocks, guaranteeing that loading spinners and disabled button states resolve even if network requests fail or return non-200 responses.
- **Backend Route Synchronization:** Aligned administrative status modification calls in `AdminView` with Cloudflare Worker routing (`POST /api/admin/user-status`), eliminating 404 URL route drift and ensuring instant UI feedback upon status updates.
- **Ownership Verification Return Typing (WP-01):** Updated JSDoc return signature in `pushCloudBackupOptimistic` (`src/utils/api.js`) to document `ownershipConflict?: boolean`, eliminating TS2353 build errors and ensuring full type consistency with `tsc -p jsconfig.json`.
- **Cloudflare Turnstile Full-Stack Integration (WP-02):** Implemented `GET /api/auth/turnstile-config` endpoint and `TurnstileWidget` component in `AuthModal.jsx` and `AuthPage.jsx`. Authentication contexts dynamically query Turnstile configuration and transmit client-solved `turnstileToken` to `/api/auth/login` and `/api/auth/register`, eliminating bot challenge lockout when `TURNSTILE_SECRET_KEY` is configured in production.
- **Unauthorized Admin Route Guard and Fallback (WP-03):** Implemented an explicit access-denied state in `App.jsx` for the `/finance/admin` route. When an unauthenticated or non-admin user navigates to the admin view, the shell renders an accessible warning banner with a "Return to Dashboard" action instead of an unstyled empty canvas.
- **ErrorBoundary IndexedDB Reset Upgrade (WP-04):** Upgraded `handleReset` in `App.jsx` to explicitly delete `TechTrekFinanceDB` in IndexedDB upon user confirmation of the "Reset app cache" action, guaranteeing that corrupted local client databases are completely cleared alongside `localStorage` and `sessionStorage` before reloading.
- **Static IndexedDB Module Inlining (WP-05):** Eliminated the redundant dynamic `import('../utils/indexedDB.js')` call in `LedgerDataContext.jsx` in favor of static module imports (`openDB`, `LEGACY_BUDGET_KEY`), resolving Vite build bundle chunk collision warnings and fixing an unexported constant bug.
